# Managing Linear

Use this skill when managing Linear issues, projects, team workflows, comments, statuses, or ticket metadata.

## Guidance

- Confirm the trigger matches the current task before applying this workflow.
- **Mandatory Why Rationale**: Every Linear issue created or updated MUST contain a clear section explaining **why** the work is necessary (the problem context, business/technical motivation).
- **ADR Reference**: When an issue involves an architectural decision with evaluated trade-offs, link or reference the ADR (`docs/architecture/adr/`).
- Keep the work scoped to the named capability and prefer narrower repo-local overrides when present.
- Preserve relevant evidence, commands, paths, and validation results in the final handoff.
- Update this skill with more specific guidance when a repeatable failure mode or workflow detail emerges.
