# Requesting Code Review

Use this skill when completing tasks, implementing major features, or before merging to verify work meets requirements

## Guidance

- Confirm the trigger matches the current task before applying this workflow.
- Keep the work scoped to the named capability and prefer narrower repo-local overrides when present.
- Preserve relevant evidence, commands, paths, and validation results in the final handoff.
- Update this skill with more specific guidance when a repeatable failure mode or workflow detail emerges.
- Apply the portable completion contract: when its review trigger is present, one
  capable independent review satisfies the review requirement; without a trigger,
  applicable checks/smoke suffice with no mandatory review. A second reviewer beyond
  the triggered review is required only for concrete identified risk or explicit
  protected repository policy. Fresh-context independence does not
  universally require a different model.
- Advisory, style, and pre-existing unrelated findings are nonblocking; subsequent
  review covers actual fixes/delta and affected integration, retaining unaffected
  settled proof.
- Maximum of three review/fix rounds for an unchanged strategy before autonomous
  strategy reconsideration.
